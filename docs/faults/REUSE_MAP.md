# Reuse map for the provisional fault-code design

Branch `chore/fault-audit` @ `main` `71e2783`. The field guide (`FAULT_CODES_FIELD_GUIDE_AND_DESIGN_DIRECTION.md`)
is **not present in the repository**, so the component list below is the one named in the audit brief.
Effort: **S** = days, **M** = one to three weeks, **L** = more than that or needs outside input (data, legal,
hardware). Estimates are the auditor's judgement, not measurements.

| Component | Status | What exists today (evidence) | What can be reused | What must be built | Effort |
|---|---|---|---|---|---|
| **Canonical fault record** | **PARTIAL** | `DtcCode` (`lib/models/vehicle_data.dart:102-155`): code, description, possibleCause, severity, action, isPending, module (`'engine'`/`'chassis'` string), component, query, remedy, failureTypeByte, isConfirmed. Description text is baked in at read time for engine codes (`obd_service.dart:1175-1184`) and re-resolved at render time. | The field set is a reasonable seed; module/platform split and the "empty means the source doesn't say" convention are sound. | Separate the *observation* (code bytes, 2- vs 3-byte, FTB, status byte, source module/address, protocol, timestamp, read method) from the *knowledge* (text per language, severity, cause, action, provenance, verification state). Add status bits, per-module identity, read time. `module` should be an enum, not a string. | M |
| **Status and failure-type decoding** | **PARTIAL** | UDS status byte parsed (`obd_pids.dart:936-947`); bit 3 → "Unconfirmed" chip; bit 0 getter unused; FTB stored, never shown. NRCs captured as a number only. | `parseUdsDtcDetailed`, `UdsDtcRecord`, ISO-TP reassembly, frame tokeniser — all tested. | Full status-bit model (testFailed, pending, confirmed, testNotCompletedSinceClear, MIL request…), FTB name table (ISO 14229/SAE J2012-DA), Mode 07/0A + 0101 reads, distinct NRC handling (0x78 wait, 0x22, 0x31, 0x33, 0x11, 0x12). | M |

## Reuse vs rebuild, in one line each

- **Keep and extend:** transport + serialisation (`_send`, poll lock, link classification, recovery), ISO-TP and
  UDS parsers (but the Mode 03 count-byte heuristic must become protocol-aware — it mis-decodes K-line replies,
  FAULT_SYSTEM_AUDIT Additions #8), chassis addressing sweep + learned-address memory, platform keying, reach-tier enums, the honesty
  conventions, the simulators and their tests.
- **Rebuild:** the engine knowledge layer (31-entry table + corrupted Hindi dictionary + unlicensed JSON), the
  resolution order, the engine read path (P-only, no 07/0A/0101, false all-clear on a silent ECU), history,
  lookup, and anything remote (packs, review queue, reporting).
- **Retire:** `DtcDictionaryHi` as a first-choice source; the stale "999 entries" comment; `DtcDatabase.getSeverityLabel`
  (unused — the screen has its own); `ObdPids.pendingDtcs` / `vehicleInfo` constants unless wired up.
